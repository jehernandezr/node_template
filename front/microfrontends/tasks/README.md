# mf_tasks

Tasks microfrontend: a CRUD example for web and mobile. It exports `tasksManifest` and all its routes live under `/tasks` (`TasksPaths`). Demo mode only: tasks has no contract yet. It accepts the `tasks/<id>` link.

## Routes

- `/tasks`: list with status filter, search and cursor pagination ("Cargar más"). At expanded width it shows the detail alongside, with the chosen task in `TasksListController.selectedId`. Search waits until the user stops typing and discards responses from old requests.
- `/tasks/new`: create task (child of `/tasks`). Its state is `TaskFormState`.
- `/tasks/:id`: detail with edit and delete (with confirmation). Child of `/tasks`, so a direct link has a navigation stack and a back button. Its state is `TaskDetailState`, controlled by `TaskDetailController`.
- `/tasks/:id/edit`: edit task (child of `/tasks/:id`). It uses `TaskFormController`, which goes from `TaskFormLoading` to `TaskFormEditing`, and only `TaskFormSaved` leads to navigation.

Each screen is a `StatelessWidget` that gets its controller with `ControllerBuilder`. Screens are gathered in `lib/src/screens/tasks_screens.dart` (`TasksScreens.list`, `TasksScreens.detail`, `TasksScreens.form`), which the manifest calls from the deferred library. Each one takes its repository from the `MicrofrontendScope` of the current identity, through `TasksData`.

## Data

`TasksRepository` (`lib/src/data/`) is the only gateway to the data. `TasksData` decides how it is created: in demo mode, `FakeTasksRepository` keeps everything in memory. Latency, programmed failures and the clock come from `DemoBehavior` in `shell_core`, which can be passed to the repository. Ids are generated by `UuidV7Generator`: UUIDv7 in creation order, so sorting by id is sorting by creation, and the pagination cursor is the last id of the page.

`changes()` emits after every create, update or delete. The list and the detail reload on that event, without waiting for the edit screen to return. The detail does not reload while deleting, so the task does not come back.

To test errors, `DemoBehavior.failNext(error, operation: TasksOperation.get)` makes the next call of that operation fail. Without `operation`, the next call of any kind fails.

## Texts

Own texts are in `lib/src/l10n/app_es.arb` (template) and `app_en.arb`. They are generated with `flutter gen-l10n` into `lib/src/l10n/generated/` (class `TasksLocalizations`). Common words (retry, cancel, edit, delete, load more) come from `AppLocalizations` in the `i18n` package.

## Tests

Screen and controller tests are in `test/screens/`, and data tests in `test/data/`. The utilities (`TasksTestApp`, `ScriptedTasksRepository`) live in `test/utils/`.

```sh
flutter analyze
flutter test
```
