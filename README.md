# Backend platform

Reusable monorepo for building microservice backends with NestJS, TypeORM and hexagonal architecture, deployed on AWS, with Flutter clients. It is the starting point for any new product: clone it, rename it and add services.

The full plan includes identity with MFA, multitenancy, auditing, messaging with retries, recoverable sagas, files, notifications, usage-based billing and end-to-end tracing.

## Current status

- **Backend:** platform libraries in `backend/libs/platform` (`kernel`, `primitives`, `config`, `observability`, `persistence`, `criteria`, `sharding`, `cache`, `bloom`, `resilience`, `rate-limit`, `messaging`, `internal-api`, `saga`), the `aws`, `postgres` and `valkey` adapters, the `platform` and `identity` contracts in `backend/libs/contracts`, and the `contracts-export` and `app-bundler` tools.
- **Front:** `web` and `mobile` shells, seven microfrontends and the shared packages, with the contracts Dart generated in `front/packages/contracts` and the shared test doubles in `front/packages/test_utils`.
- **Infrastructure:** Terraform by stacks (`network`, `platform`, `data`, `messaging`, `edge` and `service`) with a runtime chosen per service (Lambda or Fargate), `local`, `dev`, `staging` and `prod` environments, and one database per shard of each service plus the catalog.
- **AI tooling:** backend and front skills, hooks and agents in `.claude/`.

The phases, their status, the execution order by waves and the decision log are in the [plan](docs/plan/README.md), the single source for the project plan.

## Repository structure

```text
backend/        backend: external dependencies in backend/package.json, aliases in tsconfig.base.json
  libs/         platform libraries, contracts (zod) and shared utilities (Nx projects)
  tools/        contracts-export (exports the contracts to JSON) and app-bundler (esbuild)
  dist/<app>/   bundle of each app, generated by the build target (not in git)
  infra/        Terraform by stacks (infra/terraform), scripts (infra/scripts) and local environment (infra/local)
front/          Flutter pub workspace
  apps/         web and mobile shells
  microfrontends/  one package per domain
  packages/     api, auth, contracts, i18n, shell_core, shell_host, test_utils, tokens, ui, utils
  tools/        contracts_gen, Nx plugin, check_deferred_chunks.dart and check_microfrontend_boundaries.dart
docs/           plan (plan/), architecture, ADRs, per-phase designs (design/), audits (audits/) and local development
.claude/        skills, hooks and agents for the AI tooling
```

The root only holds Nx as the orchestrator (`nx.json`, `package.json`, `pnpm-workspace.yaml`) and the repository tooling (`.github/`, `.husky/`, commitlint, lint-staged, Prettier and Renovate). See [ADR 0015](docs/adr/0015-repository-structure-and-shared-code.md).

`pnpm install` creates a single `node_modules`, at the root. Backend libraries are Nx projects without a `package.json`: they are imported through TypeScript aliases (`@platform/kernel`), their code lives directly in `src/` and their tests in the `__tests__/` folder of each code folder, with shared test utilities in `__tests__/utils/`. Only apps are compiled, with esbuild, into `backend/dist/<app>`.

## Requirements

- Node 24, the version pinned in [`.nvmrc`](.nvmrc). `nvm use` or `fnm use` activates it automatically.
- pnpm 10, enabled with `corepack enable`. The exact version is in the `packageManager` field of [`package.json`](package.json).
- Flutter, the version pinned in [`front/.flutter-version`](front/.flutter-version).
- Docker with Docker Compose v2, for the local stack and the integration tests with Testcontainers.
- Terraform, the version pinned in [`backend/infra/terraform/.terraform-version`](backend/infra/terraform/.terraform-version), only if you will change the infrastructure.

## Main commands

All of them run from the root, unless another folder is given.

```bash
corepack enable                                                   # enables pnpm
pnpm install                                                      # installs Nx and the backend in a single node_modules
(cd front && flutter pub get)                                     # prepares the front
pnpm nx affected -t lint test typecheck build analyze format-check   # validates what changed (same as CI)
pnpm nx format:check                                              # checks formatting with Prettier
pnpm nx run-many -t lint test typecheck build analyze             # validates the whole workspace (pnpm check)
pnpm nx test platform-saga                                        # tests one backend project
pnpm nx test front-shell_core                                     # tests one front package
pnpm nx run contracts-export:export                               # exports the contracts to JSON
pnpm nx run contracts-export:check                                # fails if the exported JSON is out of date
(cd front && dart run contracts_gen)                              # regenerates the contracts Dart
(cd front && dart run contracts_gen --check)                      # fails if the generated Dart is out of date
pnpm nx graph                                                     # opens the project graph
```

The local stack starts from `backend/`; the steps are in [Local development](docs/local-development.md).
