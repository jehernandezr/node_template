# Rule checks

Every rule of [CLAUDE.md](../../CLAUDE.md) and of the skills in [.claude/skills](../../.claude/skills), next to the check that enforces it. A rule marked `review only` has no automatic check: the reviewer enforces it, and a finding about it is closed with the guard that the finding adds (lint rule, structure check, language check or test).

A rule is one top-level bullet of a rule section of `CLAUDE.md` or of a skill's `SKILL.md`. Numbered procedure steps, tables and the `references/` files of a skill detail those rules and have no rows of their own; the reviewer covers them.

Each rule has an id: `claude.<section>.<n>` for `CLAUDE.md`, numbered within its section, and `<skill>.<n>` for a skill, numbered through its `SKILL.md`. `.claude/guards/__tests__/rule-checks.test.mjs` fails when an id has no row here, a row names an id that no longer exists, or the rule at an id no longer starts with the words of its row, so a rule added or moved in the middle of a section moves the rows after it.

Where the checks run:

- **Pre-commit**: lint-staged runs, on the staged files only, ESLint (backend rules and guards, tooling comment rules), the language check and the structure checks (`--staged`). Whole-repository checks, Nx and tests stay in CI and the workflow gate.
- **`commit-msg`**: commitlint and the language check of the message.
- **CI**: the `guards` job (language check, tool tests, structure checks, tooling lint), the `nx` job (lint, typecheck, unit tests, contracts, generators), the `test-int` shards and the `coverage` job that merges their coverage; `ci-ok` requires all of them.
- **Workflow gate**: `.claude/guards/run-gate.mjs`, which `phase-cycle.js` runs before every review.
